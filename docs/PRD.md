# PRD: 팀 프로젝트를 위한 팀 편성 웹 앱

## 1. 배경과 목표
- 수업의 팀 프로젝트에서 학생들이 **스스로** 팀을 꾸리고, 마감 뒤 남은 학생은 **AI가 배정**을 돕는다.
- AI의 답은 믿지 않고 **앱이 규칙으로 검사**한다. AI가 실패하면 다음 모델로, 끝까지 실패하면 앱이 스스로 배정한다.
- 목표: 자동 채점 프로그램(Streamlit key로 화면 조작)이 공개하지 않은 시나리오 3개(쉬움·중간·어려움)를 끝까지 실행할 수 있고,
  확정한 팀 구성이 언제나 규칙을 지키는 것.

## 2. 사용자
| 사용자 | 로그인 | 하는 일 |
|---|---|---|
| 학생(가상 명단의 학생) | 학번 + 비밀번호(1234) | 팀 목록·팀원·역할 보기, 팀에 지원, 내 팀에 들어온 지원에 찬성/거부 |
| 관리자(교수) | 학번 `admin` + 비밀번호(Secrets의 `ADMIN_PASSWORD`) | 명단 CSV와 팀 수로 처음 상태 만들기, 모집 마감, AI 배정, 배정안 확정 |

## 3. 핵심 규칙(공고 2.3~2.5절)
- 역할 6개: 기획자, 웹 프로그래머, 프론트엔드 디자이너, 테스터, 보고서 작성자, 발표자. 학생마다 주 역할 1개, 보조 역할 0~2개.
- 확정한 팀: 모든 팀 2~4명(빈 팀 없음), 주 역할 중복 없음, 기획자와 웹 프로그래머를 **서로 다른 학생**이 1명씩(주·보조 역할 모두 인정).
- 지원: 빈 팀이면 바로 승인. 팀원이 있으면 **지금의 팀원 모두**가 찬성해야 승인, 한 명이라도 거부하면 바로 거절.
- 한 학생은 결과가 나오기 전에 다른 팀에 지원할 수 없음. 팀이 있으면 지원할 수 없음. 투표는 바꿀 수 없음.
- 막힘(접수하지 않음): 팀이 꽉 참, 같은 주 역할의 팀원이 있음, 이미 팀이 있음/결과를 기다리는 지원이 있음, 모집 마감, 필수 포함 역할 자리가 모자람.
- 승인 직전에 규칙(정원, 주 역할 중복, 필수 포함 역할 자리)을 다시 검사해 어기면 거절. 처리 순서는 투표가 끝난 순서.
- 마감: 대기 지원은 거절, 1명뿐인 팀의 학생은 팀에서 빠짐. 그 뒤 지원·투표 불가.
- 배정: 팀이 없는 학생만 넣고 기존 팀원은 옮기지 않음. 배정안은 검사 5가지(빠짐없음, 한 팀만, 2~4명, 주 역할 중복 없음, 필수 역할)를 통과해야 함.
- 규칙을 지키는 배정이 없으면 배정안을 만들지 않고 이유를 보여 줌(AI를 부르지 않음).

## 4. 기능 요구사항
| 번호 | 기능 | 받아들이는 기준 |
|---|---|---|
| F1 | 로그인(학번·비밀번호, bcrypt 해시) | 틀린 비밀번호는 "막힘", 학번만으로는 들어갈 수 없음 |
| F2 | 명단 올리기(CSV utf-8-sig + 팀 수) | 상태를 모두 지우고 학생과 빈 팀1..N을 만듦. 관리자 계정은 남김 |
| F3 | 팀 목록과 팀원·역할 보기 | 내 팀은 "내 팀"으로 구별, 팀이 없으면 "아직 팀이 없음" |
| F4 | 지원 | 결과 안내가 승인/대기/막힘으로 시작. 2.8절의 경우 지원 단추 비활성화 |
| F5 | 투표 | 결과 안내가 지원의 지금 상태(승인/대기/거절). 투표한 뒤 단추를 숨기고 "내 투표: 찬성" 표시 |
| F6 | 다른 사람의 변경 보기 | `st.fragment(run_every=3)`로 바뀐 부분만 자동으로 다시 그림(5초 이하) |
| F7 | 모집 마감 | 대기 지원 거절, 1명 팀 학생 빼기, 결과는 `unassigned`에서 확인 |
| F8 | AI 배정 | 1차→2차→3차 모델, 모델마다 120초 전체 대기 제한, 몇 차 모델을 기다리는지 표시, 검사 통과한 배정안만 보여 줌 |
| F9 | 앱 자체 배정 | 3차까지 실패하면 모든 경우를 따져(완전 탐색) 검사 5가지를 통과하는 배정을 찾음 |
| F10 | 확정 | 다시 검사한 뒤 DB에 저장, 새 브라우저에서도 남아 있음 |
| F11 | DB 일시정지 막기 | GitHub Actions가 매일 두 번 DB에 질의 |

## 5. 비기능 요구사항
- 화면 요소의 Streamlit `key`는 공고 2.7절 표와 똑같이(영문·숫자·밑줄만).
- 비밀 값(오픈라우터 키, DB 주소, 관리자 비밀번호)은 `.env`/Streamlit Secrets에만 두고, 코드·깃허브·화면에 나오지 않게(화면에는 "있음/없음"만).
- 테이블 이름은 모두 `tf_`로 시작, `schema.sql`로 남김. DB 유일성 제약으로 동시에 들어가도 먼저 온 학생만 기록.
- DB 연결은 연결 풀을 한 번 만들어 계속 다시 씀. 화면 상태는 질의 1번으로 읽음.
- 학생 이름·학번은 교수가 나눠 준 가상 명단만 씀. 특정 시나리오에 맞춘 코드는 두지 않음(규칙으로만 판단).
